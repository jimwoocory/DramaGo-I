# 类型专属写作指导：AI 图像外观描述词（character）

## 核心目标

通读并梳理全文小说剧情与人物线，把人物信息整理成稳定的 **Character Core（身份核心）+ Look Variant（造型变体）**。Character Core 只保存“这个人是谁”的稳定身份特征；婚礼、工作、便装、受伤等外观变化只进入 Variant。剧情没有给出的身份、年龄、关系、经历或事件，不得补写成既定事实。

## 风格处理原则

- 不因缺少视觉风格而暂停、追问或要求用户先选择风格；先完成角色文档。
- 若用户本轮明确指定风格，外观描述词必须贴合该风格：真人写实强调真实选角和摄影可呈现细节；2D 动漫强调线条、发色、服饰轮廓和人设符号；3DCG 动漫强调 3D 渲染质感和造型语言；Q 版强调大头小身、高辨识度和简化造型。
- 若用户未指定风格，使用风格中性的基础视觉描述：年龄段、脸型、五官、肤色、发型发色、身材、服饰、随身物和身份识别特征；不要写死镜头、媒介、渲染方式或画风。
- 图像生成环节可能会自动追加风格预设；本角色文档只需保证角色身份和跨镜头一致性，不必主动索要风格预设。

## 写作重点

- **通读锁事实**：优先提取剧情、对话、旁白中明确存在的身份和外观事实。原文缺少的年龄、亲属关系、经历、伤势、服装变化等，不得为了“完整”自行补成剧情事实。
- **视觉缺口只做建议**：为了生图确实需要但原文没有规定的纯视觉细节，可以放在 `可选视觉建议` 中，并明确它不是原文事实；这类建议不能自动升级成 locked Canon，也不能反向改变剧情。
- **可成像**：使用图像模型可解析的具体特征，例如脸型、五官、肤色、发型发色、身材、服饰、随身物，少用抽象或主观评价。
- **Core / Variant 分层**：每名角色只使用一个二级标题 `## 角色名` 作为 Character Core。十年前/十年后、婚礼/工作/便装、变身前/后等明确变化，写在该角色下面的三级标题，例如 `### 造型变体：十年前`、`### 造型变体：婚礼`。Variant 只写相对 Core 发生变化的内容，不重复改写脸型、基础发色、体型等身份核心。
- **身份与造型分离**：发型临时变化、服装、妆容、污渍、伤势阶段、配饰等通常属于 Variant/状态；除非原文明示永久改变身份外观，否则不要改写 Character Core。
- **结构自定**：每个形象条目内部结构由内容需要决定，可以使用自然段、短列表或加粗小标题；不要套固定字段，不要输出空字段。
- **视觉一致**：需要锁定 identity 的特征只在 Core 中明确一次；Variant 默认继承 Core。除非原文明确发生变化，不要在不同 Variant 中重新发明脸型、基础发色、体型和识别特征。

## 避免事项

- 不把人物设定写成剧情梗概或单纯性格标签，例如“勇敢”“腹黑”“善良”。
- 不新增原文没有的人物关系、经历、事件、伤势、持有物或造型切换；纯视觉补充必须标记为可选建议。
- 不把同一角色的婚礼装、工作装、便装拆成多个二级标题的“不同角色”。
- 不堆空泛形容词，例如“绝美”“高级”“有气场”；要落到可被图像模型识别的视觉细节。
- 不强制使用 `形象定位`、`面部特征` 等固定字段；如果使用小标题，也必须根据人物内容自然组织。
- 不主动要求用户先选择风格；未明确指定时不要默认真人写实、2D 动漫、3DCG 动漫或 Q 版风格。
