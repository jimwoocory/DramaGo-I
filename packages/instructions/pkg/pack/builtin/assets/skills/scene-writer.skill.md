# 类型专属写作指导：场景设定（scene）

## 核心目标

根据用户提供的剧情、剧本或场景提示，把空间整理成稳定的 **Scene Root（场景根）+ Scene Variant（区域/时间/状态变体）**。场景文档只呈现原文能够支持的空间事实和必要视觉建议，不把下游想象写回成剧情事实。

## 风格处理原则

- 不因缺少视觉风格而暂停、追问或要求用户先选择风格；先完成场景文档。
- 若用户本轮明确指定风格，场景描述必须贴合该风格：真人写实强调真实空间、材质、光线和摄影可呈现细节；动漫、3DCG、Q 版强调轮廓、色块、空间符号和风格化质感。
- 若用户未指定风格，使用风格中性的基础场景描述：空间结构、时间、光线、材质、核心物件、前中后景和氛围；不要写死镜头、媒介、渲染方式或画风。
- 图像生成环节可能会自动追加风格预设；本场景文档只需保证空间设定清晰、无人且可复用。

## 写作重点

- **只写关键场景**：根据剧情提取最需要建模、绘制或复用的空间；同一个物理地点只使用一个二级标题作为 Scene Root，不因镜头角度、昼夜或局部区域重复创建多个“新场景”。
- **Root / Variant 分层**：厨房、取餐口、走廊等属于同一地点的区域时，优先放在 Scene Root 下作为三级标题 `### 区域：...`；昼/夜、开灯/关灯、晴/雨等明确变化写成 `### 场景变体：...`。Variant 默认继承 Root 的空间结构、材质和固定物件。
- **事实边界**：室内/室外、门窗位置、卷帘门颜色、楼层、主要结构、固定设备等只按原文或已确认场景设定写；来源没有说明时，不得自行把室内改成室外、绿色改成银灰或新增不存在的空间结构。
- **命名有辨识度**：场景标题要具体，避免只写“房间”“街道”“办公室”等单一名词。
- **纯净无人**：画面中严禁出现人物、人影、角色姓名、字幕、水印或 UI 元素。
- **四类信息完整**：场景内容应自然覆盖环境类型、具体时间、空间氛围和视觉主要特征，但不要套固定字段。
- **Prompt 可复制**：每个场景必须包含可直接用于生图的 Prompt；Prompt 要强调 `不能出现其他人, 无人, 纯场景`，并包含 `no humans, empty, landscape only` 等约束。

## 避免事项

- 不输出 `场景提取清单`。
- 不为了画面更“电影化”擅自改变原文的内外景、时间、空间布局、门窗颜色、固定设备或区域关系。
- 不把同一 Scene Root 的不同机位、区域、昼夜状态拆成彼此无关的二级场景，除非剧情明确是不同地点。
- 不使用固定字段表、空字段或占位符。
- 不在 Prompt 中提及角色姓名、人物动作或剧情解释。
- 不把场景写成抽象气氛词堆叠；必须落到空间结构、材质、光线、核心物件和前中后景元素。
